# Troubleshooting

- **A button seems to do nothing, or something fails silently**: turn on **Debug mode** (Help & documentation → Developer tools, or `?debug=resolver` in the URL) and retry — every `console.log`/`warn`/`error` anywhere in the app (including libraries it loads), plus any uncaught error, appears on screen. This is the only practical way to see what happened on a real Android device, where devtools isn't reachable. The debug console's own **End** button turns Debug mode back off.
- **The Debug log panel got stuck open, or its close button closed something else instead**: fixed — the panel no longer shares a back-stack entry with other overlays, so it can't be silently overwritten by whatever opens next.
- **The "turn Debug mode off" button floated over the whole app, even unrelated screens**: fixed — it's now inside the debug console's own header, only visible while the console is open.
- **The bottom sheet's collapsed "peek" state cropped the walk-mode elevation chart**: fixed — the chart arrives later than the rest of the route summary (its own separate `/height` request), and the sheet now re-measures its peek height once the chart actually appears.
- **Back button skipped past search-suggestion dropdowns or an in-progress Home/Work pick**: fixed — every dropdown and pick-a-place mode now registers its own back-stack entry, so one back press closes exactly one of them.
- **"Add stop" + a category chip left a blank stop field behind, with the pick added as a separate stop**: fixed — picking a category result now fills the just-opened empty stop instead of always adding a new one.
- **Google Maps link resolution fails on one device but not another**: turn on Debug mode and retry. A quoted HTTP status with an HTML snippet (not JSON) means something in front of the Worker (Cloudflare's Bot Fight Mode/WAF, or a carrier proxy) is intercepting the request.
- **The PWA looks blank or stale after an update**: bump `SHELL_CACHE_NAME` in `sw.js` — a stale service-worker cache is almost always the cause. If that doesn't help, unregister the service worker and clear the site's storage from DevTools, then reload.
- **A new Android "Share" sheet entry doesn't show up after updating**: remove and re-add the installed PWA to the home screen once — a plain reload isn't enough for Android to pick up a `share_target` manifest change.
- **Search returns nothing, or wrong-country results, right after self-hosting**: see `GEOCODE_COUNTRY_CODES` in [Setup](SETUP.md) — the default is India-only.
- **Voice guidance was silent in the Android shell**: fixed — Android's embedded WebView has never implemented the Web Speech Synthesis API at all. The shell now uses `@capacitor-community/text-to-speech` (real native `TextToSpeech`) instead; the web/PWA build is unchanged. Side effect: this also fixed voice sounding quieter than music over Bluetooth — browser TTS commonly routes over the phone-call-quality **SCO** channel, while native TTS defaults to the music (**A2DP**) stream.
- **Voice guidance/navigation stops the moment the Android shell is minimized or the screen locks**: fixed — `WebView.onPause()` freezes all JS even though the background-geolocation foreground service keeps delivering real GPS fixes from native code. `MainActivity.onPause()` now immediately resumes the WebView so that JS keeps running.
- **A shell-only bug reappears after a rebuild that should have fixed it**: the WebView's Cache Storage and any registered service worker persist across a rebuild (only a full uninstall clears them) — the app now skips registering a service worker inside the native shell entirely and self-heals any leftover one on launch.
- **The Android shell asks for the location *permission* but doesn't turn on the device's Location *service***: these are different things — granting permission doesn't help if Location is off system-wide, and the location plugin has no way to prompt for that itself. Fixed via a custom plugin (`LocationSettingsPlugin.java`) that shows Android's own "Turn on Location?" dialog before a watch starts. No Google Play Services on the device → falls back to a plain, correctly-labeled error instead.
- **Google Maps link resolution fails with "Failed to fetch" in the Android shell specifically**: fixed — `/api/resolve-maps-url` never sent CORS headers, which the web build never needed (same-origin) but the shell does (cross-origin to the deployed Worker). Redeploy if you're on an older build.
- **Routing fails with "Could not reach the routing service" against a self-hosted Valhalla, but the public server works fine**: Valhalla's built-in HTTP server doesn't implement the `OPTIONS` method, so it can't answer a CORS preflight itself (the public demo only works because an nginx proxy in front of it answers preflight instead). Fixed by sending `Content-Type: text/plain` — one of the three CORS-"simple" types, so no preflight is triggered — Valhalla parses the JSON body regardless of declared type.
- **Routing/elevation silently uses the public Valhalla server even with `USE_SELF_HOSTED_VALHALLA: true`**: expected, not a bug, when the `SELF_HOSTED_VALHALLA_URL` Cloudflare secret hasn't been set — confirm with `wrangler secret list`. A self-hosted server that IS configured but genuinely unreachable surfaces a real error instead.
- **Elevation profile shows "Mostly flat, ↑0m ↓0m" on a route with real hills**: a self-hosted Valhalla built without `valhalla_build_elevation` silently returns a flat value for every point. The app detects an all-identical elevation response and automatically retries that one chart against the public server — masks the symptom, doesn't fix the self-hosted server's missing elevation data.
- **EV charging search silently reverts to plain OSM pins despite `OPENCHARGEMAP_ENABLED: true`**: expected, not a bug, when the `OPENCHARGEMAP_API_KEY` Cloudflare secret hasn't been set — confirm with `wrangler secret list`.
- **EV charging search shows an error instead of results**: an invalid/expired `OPENCHARGEMAP_API_KEY` — Open Charge Map has no anonymous/demo access. Check the key at [openchargemap.org](https://openchargemap.org/site/develop/api).
- **Voice guidance and background music (e.g. over Bluetooth) played at full volume on top of each other**: fixed — a custom plugin (`AudioFocusPlugin.java`) now requests transient "duck" audio focus immediately before each spoken instruction and releases it once speaking finishes. Android-shell-only; a website has no API to duck another app's audio.
- **Voice guidance sometimes said "In 0 meters, turn left" instead of just "Turn left"**: fixed — a coarse/late GPS fix could carry the remaining distance to a turn under 10m before the advance-warning callout spoke it. It now skips the distance prefix and speaks the bare instruction below that threshold.
- **The live GPS marker disappeared mid-trip, well before you'd actually arrived**: fixed — arrival used to trust a single GPS fix snapped onto the route line, which a route that loops close to itself (or, driving, an overpass/service road) could satisfy from far away. It now requires several consecutive fixes within the arrival radius *and* genuine proximity to the destination's real coordinates.
- **Tapping the locate button a second time turned tracking off instead of re-centering**: fixed — a second tap now re-centers the map on your position, matching every major map app, instead of stopping the watch and removing the marker.
- **Sharing a place from Google Maps doesn't offer this app in Android's Share sheet**: fixed — the APK now declares an `ACTION_SEND`/`text/plain` intent-filter and resolves the shared link the same way the PWA's own `share_target` does. Requires a rebuild (`npm run cap:sync`) to take effect on an already-installed APK.
